# My Portfolio

個人のポートフォリオ兼ブログサイトです。

これまでに制作したプロダクトや参加したプロジェクト、使用している技術、これまでの活動などを掲載しています。  
また、MDXを利用したブログ機能を持っており、技術記事や開発記録などもこのサイトで公開しています。

このリポジトリはポートフォリオサイトとして運用するだけでなく、Web開発や設計、Git/GitHubを利用した開発フローなどを学ぶためのプロジェクトとしても利用しています。

## Tech Stack

現在公開しているサイトは、主に以下の技術で構成されています。

- React
- TypeScript
- Vite
- React Router
- MDX
- remark / rehype
- highlight.js
- ESLint
- GitHub Actions
- Vercel

### `src/articles`

ブログ記事を管理しています。

記事はMDX形式で記述しており、Markdownによる文章表現に加えて、必要に応じてReactコンポーネントを利用できる構成にしています。

### `src/components`

サイト内で利用するUIコンポーネントを管理しています。

ブログ表示用のコンポーネントや、MDX内で利用するコンポーネントなどもここに含まれています。

### `src/data`

ポートフォリオに表示するデータを管理しています。

主に以下のような情報を含んでいます。

- 制作物
- 使用技術・スキル
- 経歴
- ナビゲーション情報

### `src/views`

ページ単位のUIを管理しています。

現在は主に以下のページがあります。

- ポートフォリオトップ
- ブログ一覧
- ブログ記事詳細
- 404ページ

## Blog

このサイトにはブログ機能を実装しています。

記事はMDXで管理しており、技術的な学習記録や開発についての記事などを掲載しています。

ブログそのものの実装についても、このサイトで新しい技術や設計方法を試すための題材として利用しています。

## Learning Project

このリポジトリは、完成したポートフォリオを公開することだけを目的としていません。

自分自身の学習や実験の場としても利用しています。

例えば、以下のようなことをこのリポジトリを通して学んでいます。

- React / TypeScriptを利用したフロントエンド開発
- コンポーネント設計
- Webサイトの構成や設計
- MDXを利用したコンテンツ管理
- Git / GitHubを利用した開発フロー
- ブランチを利用した変更管理

ポートフォリオ自体も、学習に合わせて継続的に変更・改善しています。

## Next.js Migration

現在、このサイトを **Vite + ReactからNext.jsへ移行中** です。

既存のサイトを一度に置き換えるのではなく、現在のReact版を維持しながら段階的に移行しています。

移行作業では専用のブランチを利用しています。

```text
migration/nextjs
chore/nextjs-foundation
```

Next.jsの基盤では、App Routerを利用した構成への移行を進めています。

また、移行期間中は既存のVite環境も動かせるようにし、React版との比較や動作確認を行いながら開発しています。

この移行も、このサイトを学習プロジェクトとして利用する取り組みの一つです。

Next.jsへの移行を通して、フレームワークを利用したWebアプリケーション設計や、レンダリング方式、ルーティング、コンテンツ管理などについて理解を深めることを目的としています。

## Future Plans

今後は、現在フロントエンドのリポジトリ内で管理しているコンテンツと表示ロジックを、より明確に分離していく予定です。

特に、以下のような分離を検討しています。

- ブログ記事のフロントエンドからの分離
- `src/data` で管理しているポートフォリオ情報の分離

現在は、ブログ記事をMDXファイルとして、制作物・スキル・経歴などの情報をTypeScriptファイルとして、フロントエンドのソースコードと同じリポジトリ内で管理しています。

将来的には、これらのコンテンツをフロントエンドの実装から独立させ、フロントエンド側はコンテンツを取得して表示する責務に集中できる構成を目指しています。

これにより、以下のような点についても学習・検討していきたいと考えています。

- フロントエンドとコンテンツ管理の責務分離
- APIを介したデータ取得
- CMSやヘッドレスCMSなどを利用したコンテンツ管理
- データ更新とアプリケーションデプロイの分離
- より保守しやすいアーキテクチャ設計

Next.jsへの移行と合わせて、単にフレームワークを変更するだけではなく、サイト全体の責務や構成そのものも段階的に見直していく予定です。

## Development

依存関係をインストールします。

```bash
npm install
```

開発サーバーを起動します。

```bash
npm run dev
```

ビルドします。

```bash
npm run build
```

Lintを実行します。

```bash
npm run lint
```

型チェックを実行します。

```bash
npm run typecheck
```

## Git Workflow

`main` ブランチは、基本的に常に公開可能な状態を維持します。

変更内容ごとにブランチを作成し、Pull Requestを通して`main`へ反映する方針です。

主なブランチ命名規則は以下の通りです。

```text
feature/<name>   # 機能追加
article/<slug>   # ブログ記事
fix/<name>       # バグ修正
refactor/<name>  # リファクタリング
chore/<name>     # 設定・CI・依存関係など
docs/<name>      # ドキュメント
```

開発ルールの詳細については、`AGENTS.md`に記載しています。
