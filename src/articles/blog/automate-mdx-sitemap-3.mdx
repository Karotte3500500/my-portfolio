## 前回と同じ問題ではない
```
tsc -b && vite build
```
これは、**差分の型チェックをした後に、全体のビルドをするという意味**です。

```tsc -b```では、前のビルドの前に変更されたファイルを確認し、型を確認するコマンドです。
一方で```vite build```は全体をビルドするコマンドです。
そして、この２つのコマンドを```&&```で結んでいます。
```&&```は左側のコマンドが正常に実行できた場合、右側のコマンドを実行するという記号です。

```tsc -b```が失敗した場合はviteは立ち上がらないため、
仮に```glob```で失敗した場合はtscのエラーが発生するはずです。

しかし、今回の場合```vite v8.1.3 building ...```というログが出ているため、
viteのビルドが動いていることが分かり、**```glob```で問題が発生していない**ことが分かります。

<br/>
また、今回の場合、```vite.config.ts```の読み込みも成功していると考えられます。

```ts
const blogSitemapEntries = getBlogSitemapEntries();
```
```vite.config.ts```を読み込む際に、上の処理が実行されます。
```txt
vite.config.tsを読み込む
  ↓
getBlogSitemapEntries()を実行
  ↓
MDXファイルを探す
  ↓
Frontmatterを読み取る
  ↓
公開記事のURL一覧を作る
  ↓
Viteのビルドを開始
```
そのため、```vite.config.ts```での処理順は上記のように進みます。

もし、```getBlogSitemapEntries()```で例外が発生した場合は、viteは設定ファイルを最後まで読み込むことができません。
しかし、```✓ 73 modules transformed.```まで進んでいるため、```vite.config.ts```の読み込みと、
```getBlogSitemapEntries()```は少なくとも例外を出さずに完了したと考えられます。

そのため、前回までの**記事の一覧を取得することに失敗していたわけではなさそう**です。

```error

open '/home/XXXX/dist/robots.txt'

at generateSitemap (file:///home/XXXX/node_modules/vite-plugin-sitemap/dist/index.js:11199:5)

at plugin.<computed> (file:///home/XXXX/rolldown/dist/shared/bindingify-input-options-BsDhfYrS.mjs:1961:18)
{

    code: 'PLUGIN_ERROR',
    syscall: 'open',
    path: '/home/XXXX/dist/robots.txt', pluginCode: 'ENOENT',
    plugin: 'vite-plugin-sitemap',
    hook: 'closeBundle'
}
```
スタックレースを確認すると、```vite-plugin-sitemap```による処理と```writeFileSync()```が見当たります。
```vite-plugin-sitemap```はサイトマップを生成するプラグインであり、
```writeFileSync()```は最終的に```robots.txt```を書き込むための処理です。

```txt
vite-plugin-sitemapのcloseBundle
    ↓
generateSitemap()
    ↓
writeFileSync()
    ↓
dist/robots.txtへの書き込みに失敗
```

そして、上記のようにサイトマップを生成するためのプラグインが、
```writeFileSync()```を使って直接```robots.txt```を書き換えようとして失敗していたのです。

これは、ビルド終了時にプラグインが想定していた状態で```dist```ディレクトリが存在していなかったことが原因だと考えられます。

Vite8ではビルド基盤がRollupからRolldownへ変更されているため、
既存プラグインが想定していた実行タイミングや前提が合わなくなった可能性が考えられますが、
断定はできません。
ただ、```vite-plugin-sitemap```が```closeBundle```内で```dist```に直書きしようとした処理が失敗したことは確かでした。

# プラグインの自作
ということで、```dist```へ直接書き込むのではなく、サイトマップと```robots.txt```をViteの正式ビルドの
成果物として登録する方針にしました。

そのために、```generateBundle```と'''emitFile()'''を用いることにしました。
```ts
generateBundle() {
    this.emitFile({
        type: "asset",
        fileName: "sitemap.xml",
        source: sitemapXml, 
    });
}
```
Viteプラグインでは、```generateBundle```内から'''emitFile()'''を呼ぶことで、
追加ファイルをビルド成果物として登録できます。

この方法では、自作プラグインはファイルの内容だけを生成し、
実際にどのディレクトリへどのタイミングで書き込むのかはViteに任せられます。

これにより、```sitemap.xml```と```robots.txt```の内容を作り、
```emitFile()```でViteへ渡す処理だけを実装すれば良いです。

## サイトマップXMLを生成

サイトマップへ登録する１ページ分の型は、以下のようにしました。
```ts
export type SitemapEntry = {
    path: string;
    lastmod?: string;
};
```
lastmodを任意にすることで、LPのような更新日を指定しないデータの作成も可能です。
```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
    <url>
        <loc>
            https://nawata.me/
        </loc>
    </url>
    <url>
        <loc>
            https://nawata.me/blog 
        </loc>
    </url>
    <url>
        <loc>
            https://nawata.me/blog/created-portfolio
        </loc>
        <lastmod>
            2026-07-18
        </lastmod>
    </url>
</urlset>
```
URL一覧をXMLへ変換すると、最終的には上記のような内容になります。

## 最終的な```vite.config.ts```
最終的な構成では、まずNode.js側でブログ記事のサイトマップ情報を取得します。
```ts
const blogSitemapEntries = getBlogSitemapEntries();
```

そして、その結果を自作したViteプラグインへ渡します。

```ts
sitemapPlugin({
    hostname: "https://nawata.me",
    entries: [
        {
            path: "/",
        },
        {
            path: "/blog",
        },
        ...blogSitemapEntries, 
    ], 
});
```

# 最後に

はじめは、Reactアプリ側の記事一覧を```vite.config.ts```でそのまま使いまわそうとしていました。

しかし、React側の記事取得処理は、Viteの```glob()```に依存しており、
Node.jsで動く```vite.config.ts```からでは使えませんでした。

そこで、MDXのFrontmatterを採用し、React側の処理とNode.js側の処理を分離しました。

さらに、既存のサイトマッププラグインが正常にファイルを書き出せない問題が発生したため、
Viteの```emitFile()```を使用するローカルプラグインへ置き換えました。

今回の作業を通じて、```vite.config.ts```はTypeScriptで書かれているが、
Reactアプリと同じ環境で動いているわけではないことを知りました。

同じプロジェクト内のコードであっても、どこで実行されるかを意識する必要性を学びました。

また、ビルド時にファイルを生成する場合、
出力先へ直接書き込むよりもビルドツールが準備している仕組みを使うほうが安全であると感じた。
